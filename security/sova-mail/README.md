# Совина почта — настройка (не активирована)
1. Создать отдельный проект https://supabase.com/dashboard (не использовать базу лайков).
2. SQL Editor → New query: выполнить `schema.sql` один раз в пустом проекте.
3. Authentication → Users → Add user → Create user. Ввести собственную почту и сильный пароль непосредственно в Supabase, подтвердить email. Скопировать UUID пользователя. В SQL Editor выполнить отдельно: insert into sova_private.admins(user_id) values ('UUID'); Не передавать пароль.
4. Authentication: включить Anonymous sign-ins, отключить публичную регистрацию постоянных пользователей, если доступна отдельная настройка (не отключать anonymous sign-ins). В Cloudflare Turnstile создать виджет для belaya-mgla-sova58.github.io. В Supabase Auth включить CAPTCHA Turnstile и ввести secret непосредственно в Dashboard. Проверить настройки лимитов анонимной авторизации.
5. В `sova-mail-config.js` указать только Project URL, publishable key (или legacy anon key), Turnstile Site Key. НЕ service_role, sb_secret, secret CAPTCHA или пароль. enabled=true только для тестирования; publicLauncher=false оставляет кнопку скрытой.
6. Проверить с двумя отдельными профилями браузера: каждый видит только своё обращение, не может изменить статус, прочитать чужой файл или назначить себя администратором. Администратор видит оба и может ответить. Проверить загрузку PNG/JPEG/WebP до 5 МБ и отказ при превышении. Проверить отклонение запросов без CAPTCHA и без сессии. Проверить подписанные ссылки и отсутствие публичного доступа к bucket. Только после этого установить publicLauncher=true и подключить кнопку на остальных страницах.
7. Анонимный игрок видит ответы на том же устройстве и в том же браузере, пока сохранена сессия; не обещать восстановление на другом устройстве. Статусы меняет только администратор. Уведомления при открытой странице через периодическое обновление, не фоновые push.
8. Лимиты базы: 5 обращений/сутки, 20 сообщений/час на игрока; 3 вложения на сообщение, до 5 МБ на файл, до 30 загрузок за сутки на игрока. Публичный приём требует наблюдения за расходом Storage и очистки ненужных объектов владельцем. Незавершённая загрузка может оставить файл в bucket; удалять через админский dashboard. Перед эксплуатацией установить правила хранения и удаления данных. Не отправлять пароли, платежные данные и личные сведения.
