## 2. Нерушимые требования владельца

1. **Нельзя откатывать весь сайт к старой версии**, возвращать старые шапки или старое оформление, заменять файлы архивными копиями без отдельной просьбы.
2. **Менять только явно запрошенную страницу и её конкретный элемент.** Не «улучшать заодно» меню, главную страницу, другие события, калькуляторы, общие стили и скрипты.
3. **Ничего не удалять без просьбы:** тексты, рабочие функции, изображения, иконки других страниц, ссылки, анимации и мобильную адаптацию.
4. Перед записью проверять текущий файл и его Git SHA; делать точечные изменения, не перезаписывать файл из устаревшего шаблона. Сохранять историю в Git.
5. Если файл кажется пустым или повреждённым, **не восстанавливать вслепую**. Проверить содержимое, размер, актуальные коммиты и последнюю рабочую редакцию конкретного файла. Никогда не возвращать весь сайт назад ради исправления одной страницы.
6. После изменений проверять нужную страницу и мобильное отображение, объяснять, **что именно** изменено. Не писать «всё проверено», если проверено только сохранение в GitHub. Если публикация GitHub Pages задерживается или мешает кэш, сообщить об этом отдельно.
7. Не сообщать о завершённой публикации или исправлении, пока действие и результат не подтверждены. При отсутствии доступа честно объяснить ограничение.

## 3. Оформление и стиль

- Сайт о Whiteout Survival («Белая Мгла: Выживание»). Настроение: тёмный космос, зимнее фэнтези, яркие холодные и разноцветные неоновые акценты, сияние и белая сова. Сохранить уже утверждённые новые шапки событий.
- У страниц могут быть **разные цвета и собственные элементы оформления**. Не унифицировать всё без запроса.
- Для последних изменений событий пользователь показал образец **двух вытянутых светящихся угловых линий**: **сверху слева и снизу справа**. Линии длинные, отчётливо яркие, немного толстые, с мягкой анимацией/пульсацией; они должны заменить прежние декоративные иконки только там, где это согласовано.
- Скриншот от пользователя задаёт точную геометрию и расположение элементов. Не добавлять симметричные линии в остальные углы, если пользователь не попросил.
- На телефоне всё должно оставаться читаемым: не перекрывать заголовки и кнопки, не создавать горизонтальную прокрутку.

## 5. Как выполнять любое изменение

1. Уточнить точный запрошенный результат по последнему сообщению и изображению; не задавать повторно вопросы, на которые уже дан ответ.
2. Получить текущую версию **именно нужного** файла из `main`; проверить её размер, состояние, SHA и последние затронувшие её коммиты.
3. Определить минимальный набор правок и убедиться, что CSS/JS не воздействует на другие страницы.
4. Изменить только необходимые файлы. Не использовать старый HTML целиком как замену.
5. Проверить синтаксис/целостность, ссылки, desktop/mobile и по возможности опубликованный результат.
6. Зафиксировать, какой файл и что в нём изменено; при необходимости обновить **раздел 6** этого документа с новой точкой продолжения.
